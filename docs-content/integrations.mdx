## Background Workers

FRIDAY's true power lies in its asynchronous processing. We utilize a robust RabbitMQ implementation via `QueueService` to handle integrations without blocking the main Next.js thread.

## Git Integrations (GitHub + GitLab)

Git integrations allow you to link issues to Pull Requests (PRs) or Merge Requests (MRs) automatically. 

**Technical Flow:**
1. **Registration**: FRIDAY registers a webhook URL in your GitHub/GitLab repository.
2. **Event Parsing**: When a PR or Commit is pushed, the `github-sync.worker.ts` (or GitLab equivalent) receives the payload.
3. **Smart Linking**:
    - The worker scans the commit message or PR title for issue keys (e.g., `PROJ-123`).
    - It updates the `PmIssue` record to link the external URL.
    - **Auto-Transition**: If the commit message contains "Fixes" or "Closes", the issue status is automatically moved to `DONE` or `IN_REVIEW`.

**Configuration:**
- **Webhook Secret**: Used to verify the authenticity of the incoming request.
- **Access Token**: Scope must include `repo` (GitHub) or `api` (GitLab).

## Jira Import System

The Jira Import System allows users to bulk import projects, issues, statuses, and assignees directly into FRIDAY.

**Technical Flow:**
1. **Job Initialization**: When you trigger an import, the system creates a `PmImportJob` record with a `PENDING` status.
2. **Asynchronous Execution**: The import process runs in the background (via `setImmediate` in dev or a dedicated worker in prod) using the `runJiraImport` function.
3. **Data Mapping**: Jira issues are fetched via REST API v3. The system maps Jira states to FRIDAY's internal schema:
    - **Status**: Maps Jira's status names (e.g., "In Progress") to FRIDAY's `TODO`, `IN_PROGRESS`, `DONE`, or `BLOCKED`.
    - **Priority**: Maps Jira priorities (Blocker, Major, Trivial) to FRIDAY's `URGENT`, `HIGH`, `MEDIUM`, `LOW`, `NONE`.
    - **Users**: Attempts to resolve assignees by email address; falls back to the project creator if the user doesn't exist in FRIDAY.
4. **Progress Tracking**: The UI polls the `pmIntegrations.importJobStatus` tRPC endpoint to show a live progress bar.

**Configuration:**
- **Jira Domain**: Your Atlassian domain (e.g., `company.atlassian.net`).
- **API Token**: An Atlassian API Token generated from your security settings.
- **Project Key**: The short key of the Jira project (e.g., `PROJ`).

## Calendar Sync (Google & Outlook)

FRIDAY can automatically sync your due dates and sprint milestones to your external calendar.

**Technical Flow:**
1. **Integration Link**: Users connect their Google or Outlook account via OAuth. Tokens are stored encrypted in the `Integration` table.
2. **Mutation Trigger**: When an issue `dueDate` is updated or a new issue is assigned, the `syncIssueToCalendar` function is invoked.
3. **Event Management**:
    - The system checks for an existing `externalEventId` in the integration metadata.
    - If it exists, it performs a `PATCH` update; otherwise, it `POST`s a new event.
    - Description includes a direct link back to the FRIDAY issue.

**Worker Strategy (`CalendarSyncWorker`):**
In high-volume environments, we use a dedicated worker that listens to the `calendar.sync` queue. This ensures that slow third-party API responses don't impact the responsiveness of the PM interface.

## SSO + Login Integration

A robust simulated Single Sign-On endpoint that manages enterprise connections.

**Flow:**
1. The SSO integration endpoint (`/api/auth/sso`) receives a response from an SSO provider (e.g., Okta, Auth0, Azure AD).
2. It accepts a `base64` encoded JSON identity payload.
3. The system maps the identity payload and uses an upsert to either create a new user or update an existing session.
4. Returns the verified identity along with a success message, prompting the client to initialize a NextAuth `signIn()` utilizing the credentials.

**Payload Shape inside the token:**
```json
{
  "email": "user@example.com",
  "name": "Alice",
  "ssoProvider": "okta",
  "ssoId": "user-unique-id-from-provider",
  "image": "https://example.com/avatar.jpg"
}
```

<Callout type="warning">
  Ensure your `RABBITMQ_URL` is configured in `.env`. Without a running broker, webhook events for GitHub/GitLab will fail to process.
</Callout>
